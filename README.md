# 法律知识库生产 Skill

[English README](README.en.md) · [中文 Skill 全文](SKILL.zh-CN.md) · [English Skill](SKILL.md)

说出想学习的法律领域，就能让 AI 在 Obsidian 中建立学科导航、概念卡、规范卡、案例卡和专题关联，再按教学、法务实务、考试、研究或探索目的组织成果。

本 Skill 是给 AI 执行的工作方法，不是 Obsidian 插件。v2 支持从零建库；不要求先准备一批资料或确定精确的研究问题。

## 从这句话开始

安装后，在 Codex 对话中发送：

```text
使用 $legal-knowledge-base。我想学习 AI 数据合规，
主要用于中国大陆企业法务工作。
请在我的 Obsidian 法律库中建立独立的学科子库，
先搭学科导航，再完成一个可用的入门专题。
我的 Obsidian 库路径是：填入你的实际路径。
```

如果没有明确用途，也可以直接说“我想学习劳动法，帮我在 Obsidian 建库”。AI 会结合上下文确认存放位置和法域，先按探索目的搭建；用途可以后来调整。已有教材、大纲、PDF、Word 或题目时，直接提供文件或路径。AI 使用可用的读取/OCR 能力；无法可靠读取的部分会保留待核记录。

## 会得到什么

- 一份建库配置：学科、法域、时间范围、使用目的、路径和本次范围。
- 一份学科导航：核心问题、先修概念、模块关系、学习顺序、已建内容与待补资料。
- 有来源的概念、规范、案例与专题笔记，能沿链接往返查找。
- 与用途匹配的成果，及有真实使用证据时的反馈记录。
- 结构检查结果、当前覆盖范围和下一步任务。

首批交付是一组贯通的实质内容，不代表已经穷尽该领域。资料不足时会明确指出缺口。

## 不同目的，共用知识

| 目的 | 成果示例 | 反馈来源 |
|---|---|---|
| 教学 | 讲授结构、逐页 PPT 骨架、讨论题与出处备注 | 试讲、用户审稿、学生提问 |
| 法务实务 | 问题分析、审查表、流程、评估底稿 | 材料试用、业务与法务审阅 |
| 考试 | 考点地图、练习与解析、错因记录 | 真实作答、评分标准、失分原因 |
| 研究/探索 | 概念辨析、文献与问题地图、研究小结 | 追问、反例、应用尝试 |

用途可以多选和改变。不会统一要求每个人考试，也不会因为生成了笔记就标“已掌握”。没有反馈时不阻塞建库。PPT 骨架是 Markdown 内容；真正的 PPTX 需要相应文件生成能力。

## 法律数据库连接：检索前必查

每次开始法规或案例检索，必须先检查 MCP 中是否有威科先行、北大法宝等专业法律数据库，并用已有授权的只读能力验证能否访问。可用时优先用于相应检索；未发现或连接失败时说明原因，再通过官方来源继续。发现工具不等于接通，搜索成功也不等于取得全文。

检查结果和实际来源会记录在建库配置、来源索引中。这条规则不表示 Skill 自带数据库账号或能够自动开通订阅。详见[连接器检查流程](references/legal-source-connectors.md)。

## 目录与关联

同一 Obsidian 库内可以有多个平行学科子库。基础层为 `00-Inbox`、`01-法规层`、`02-案例层`、`03-专题层`（含概念卡）与选用的模板；教学、法务实务、其他产出和反馈目录按需要启用。已有库优先保留原约定。

“专题地图/MOC”是一份将相关笔记组织起来的导航页；“frontmatter”是每篇笔记顶部记录类型、状态和关联的字段；“双链/wikilink”是 Obsidian 的 `[[笔记路径]]` 链接。

v2 在元数据中统一使用链接列表，正文也保留可点击索引。法条能反查案例，专题能汇总成员，成果能回到依据。Dataview 是可选增强；未启用时仍可使用完整的显式链接清单。

## 安装到 Codex

将整份文件夹复制到 `~/.codex/skills/legal-knowledge-base/`，或你配置的 `$CODEX_HOME/skills/legal-knowledge-base/`。下载包的外层目录如果带“开源版”等后缀，请把安装目录命名为 `legal-knowledge-base`，保留内部文件。

Mac 中可以在 Finder 的“前往文件夹”中粘贴上面的目录位置。重新加载可用技能后，在 Codex 对话中使用 `$legal-knowledge-base`。

```text
legal-knowledge-base/
├── SKILL.md                  英文执行入口
├── SKILL.zh-CN.md            同版本中文说明
├── README.md / README.en.md  中英使用说明
├── agents/openai.yaml       界面名称与调用提示
├── references/              学科设计、共享字段、来源核验方法
├── assets/templates/        可直接适配的笔记模板
├── scripts/validate_vault.py 只读结构检查
└── tests/                   检查工具的回归用例
```

参考文件和笔记模板目前使用中文；中英入口共享同一套字段，避免出现两套不兼容的库。

## 检查与已有库

检查工具需要 Python 3.9+ 和 PyYAML，在 Skill 目录运行：

```sh
python3 scripts/validate_vault.py --vault "/你的/Obsidian库" --subject "数据合规知识库"
```

工具只读文件，检查 v2 字段、状态、链接、专题登记和反向索引；不联网核验法条，也不运行 Obsidian 中的 Dataview。没有 Python/PyYAML 时，AI 可按字段规范执行等价检查。

旧库需先适配其字段和值类型；本工具不会自动重命名或迁移文件。更新 Skill 也不会自动改写你的现有学科库。

## 文件与维护

[中文流程](SKILL.zh-CN.md)适合完整审阅；[用途设计](references/subject-design.md)说明怎样适应不同目标；[字段规范](references/card-schemas.md)规定模板和查询如何配合；[来源核验](references/authority-tiers.md)规定如何记录版本与效力。

英文入口与中文说明同步维护，版本均为 2.1（笔记字段仍使用 v2）。规则变化时，流程要求沿关联查找受影响内容并标记待复核；后台定期监控需要另外实际设置任务。
