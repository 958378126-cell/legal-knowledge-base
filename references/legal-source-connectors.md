# 法律数据库 MCP 检查与检索路由

适用于法规、法条、司法解释、案例及其版本状态的外部检索。此项是检索前的硬规则；整理已有附件或仅更新 Skill、且未发起外部法律检索时，不必制造无关查询。

## 1. 先发现真实可用的连接器

检查本次会话暴露的工具及平台提供的工具发现/搜索能力；优先查找“威科先行 / Wolters Kluwer / WK China”和“北大法宝 / PKULaw”，同时识别其他符合任务的专业法律数据库。读取实际工具描述与参数，区分法规检索、全文、案例、沿革和引用辅助功能。

两个具名数据库均须有检查结果；未暴露或未发现时记“未发现”，不能据此断言该产品没有 MCP 服务。无工具发现机制时说明“本会话无法进一步发现连接器”。可以记录当次发现的工具名，不能把某台电脑上的工具名硬编码为所有使用者都拥有的依赖。

发现已有连接器后使用它提供的已授权能力；不臆造 MCP 地址、接口、插件或账号，不把“加法规链接”工具当成法规原文/效力检索工具。需要新增服务、购买权限或用户登录才能继续时，说明具体缺口，保留官方检索路径；不把安装或授权额外服务当成这条检查规则的默认要求。

## 2. 用最小的真实读取确认能力

有只读健康/状态工具时可先用它，但服务健康不代表具体库权限。随后使用当前任务实际需要的公开法规标题、条文或案例关键词发起一次小范围查询。没有状态工具时，首个真实检索直接承担检查作用，不额外编造测试问题。发送完成检索所需的最少信息，不为测试连接上传整份业务材料。

区分以下状态，并记录具体证据：

| 状态 | 可以说明什么 | 下一步 |
|---|---|---|
| 未发现 | 当前会话未暴露/发现对应入口 | 记录发现范围，改用其他可用专业库或官方来源 |
| 已发现，未实测 | 工具存在，尚无调用结果 | 在实际检索时执行只读查询；不能写“已接通” |
| 已实测可检索 | 查询得到正常响应 | 使用合适功能；如需原文，继续验证原文访问 |
| 查询成功但无命中 | 本次条件下没有检索结果 | 调整检索词或补充来源；不推断法规/案例不存在 |
| 需授权/权限不足 | 当前账号不能使用该功能或资料 | 标明受限范围，转可用来源 |
| 调用失败 | 连接、超时或服务错误 | 按错误信息处理；同一失败不反复无变化重试 |

搜索列表、摘要、全文、版本信息分别按实际返回内容报告；不要把查询成功扩大成“数据库所有模块都能用”。

## 3. 使用与交叉核验

相关专业库可用时，优先用于法规、案例及关联资料检索；根据法域和已授权功能选择，不强制每个问题调用所有数据库。不适用或不可用时使用制定机关、法院、监管机关、官方法律数据库等来源。先向用户简要说明连接检查结果和采用的检索路径，不以普通搜索结果冒充专业数据库查询。

专业数据库是检索渠道，法律效力仍取决于文件本身。保留数据库记录链接/编号、原始发布机关、版本、条款定位和实际访问日期；当前效力、修订沿革及关键结论按 [authority-tiers.md](authority-tiers.md) 核验。可取得官方原文时保留官方入口；只能取得数据库文本时如实标注出处及未完成的官方交叉核验，不虚构官方核验记录。

发生来源冲突时记录差异，回到对应版本的一手资料处理。只取得摘要时不能补写全文或宣称已核对完整条文。

## 4. 把检查结果留在库里

在 `00-建库配置.md` 的“法律数据库连接检查”区域记摘要，在来源索引的“检索记录”记与实际资料相关的调用结果：日期、数据库/入口、能力、状态、最小查询条件或调用依据、结果范围、替代路径。错误信息只记录与诊断有关的内容，不保存凭据。

同一任务复用已验证状态；遇到鉴权、订阅、工具或会话变化时重新检查。交付时明确“实际用过哪些数据库、哪些只发现了入口、哪些走了官方来源”。结构检查脚本不验证网络连接，不得用脚本通过代替连接实测。
